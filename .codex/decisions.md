# Архитектурные решения

## ADR-001 — Модульный монолит для MVP

- **Статус:** proposed
- **Решение:** React/TypeScript frontend + FastAPI backend + PostgreSQL, развёртывание через Docker Compose.
- **Почему:** минимальная эксплуатационная сложность при достаточных границах модулей.
- **Альтернатива:** микросервисы — отклонены до появления измеримой необходимости независимого масштабирования.

## ADR-002 — PostgreSQL как источник продуктовой аналитики

- **Статус:** proposed
- **Решение:** события и агрегаты продукта хранятся и вычисляются в PostgreSQL.
- **Почему:** транзакционная согласованность и проверяемость метрик.
- **Альтернатива:** аналитика по логам ELK — отклонена как нестабильный источник бизнес-фактов.

## ADR-003 — Наблюдаемость без ELK на старте

- **Статус:** proposed
- **Решение:** OpenTelemetry Collector, Prometheus, Grafana, Loki и error tracking; Tempo/Elasticsearch добавляются по фактической потребности.
- **Почему:** покрывает диагностику при меньшей стоимости эксплуатации.

## ADR-004 — Bitrix24 остаётся системой исполнения задач

- **Статус:** proposed
- **Решение:** приложение владеет проблемой, триажем, аудитом и аналитикой; Bitrix24 владеет задачей исполнения.
- **Почему:** исключает два конкурирующих таск-трекера.
