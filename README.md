# App Feedback Collection

Внутреннее приложение для прозрачного сбора, разбора и устранения проблем в проектах компании. Оно объединяет обратную связь сотрудников, контроль качества, назначение ответственных, дедупликацию, задачи Bitrix24 и понятную живую аналитику.

> Статус: этап проектирования. Код продукта ещё не создан; требования и архитектурные решения уточняются в брифе.

## Зачем нужен продукт

- дать каждому сотруднику простой канал сообщения о проблеме;
- показать компании, что проблемы не скрываются, а управляемо устраняются;
- собрать единый реестр проблем по проектам, людям, причинам и статусам;
- дать отделу качества рабочее место для разборов и собственных проверок;
- превращать подтверждённые проблемы в контролируемые задачи Bitrix24;
- показывать динамику без публичного унижения и ложных рейтингов «кто хуже».

## Ключевые сценарии

1. Сотрудник сообщает о проблеме, прикладывает контекст и доказательства.
2. QA/администратор уточняет карточку, связывает дубликаты и классифицирует первопричину.
3. Ответственный подтверждается отдельно от автора, исполнителя и владельца процесса.
4. Из подтверждённой проблемы создаётся или связывается задача Bitrix24.
5. Статусы синхронизируются, решения и проверка результата сохраняются в истории.
6. Сотрудники видят общую картину, динамику и карточки в пределах своих прав.
7. Руководитель открывает проект, подразделение или сотрудника и изучает факты и тренды.

## Роли

- **Сотрудник** — создаёт сообщения, дополняет свои записи, видит разрешённую аналитику.
- **QA / отдел качества** — создаёт проблемы по контрольным точкам, проводит триаж, объединяет дубли, проверяет исправления.
- **Руководитель проекта** — управляет приоритетами и ответственными в своих проектах.
- **Исполнитель** — получает задачи, обновляет решение и предоставляет подтверждение.
- **Администратор** — управляет справочниками, ролями, правилами видимости и интеграциями.
- **Аудитор / руководство** — читает неизменяемую историю и агрегированную аналитику.

## Основные модули

- форма обратной связи и фиксации QA-наблюдений;
- реестр проблем с фильтрами, сохранёнными представлениями и массовыми действиями;
- рабочее место триажа и дедупликации;
- карточка проблемы с доказательствами, связями, решениями и аудитом;
- проекты, контрольные точки и классификаторы;
- интеграция с задачами и пользователями Bitrix24;
- дашборды компании, проектов, подразделений и сотрудников;
- уведомления, SLA и эскалации;
- администрирование ролей, видимости, справочников и интеграций.

## Предлагаемый стек

| Слой | Выбор для старта |
| --- | --- |
| Встраивание в Bitrix24 | локальное приложение Bitrix24, OAuth/REST через backend |
| Frontend | React + TypeScript + Vite, дизайн-система и ECharts |
| Backend | FastAPI + Python |
| Основная БД | PostgreSQL + Alembic |
| Фоновые задачи | Redis + Celery после появления реальной асинхронной нагрузки |
| Файлы | S3-совместимое объектное хранилище |
| Наблюдаемость | OpenTelemetry Collector + Prometheus + Grafana + Loki; Tempo при необходимости трассировок |
| Доставка | Docker Compose на первом этапе, Caddy/Nginx, CI/CD из `main` |

Elasticsearch и Logstash не входят в MVP: для продуктовой аналитики источником истины остаётся PostgreSQL, а для логов дешевле и проще начать с Loki. Elasticsearch стоит добавлять только при подтверждённой потребности в полнотекстовом поиске большого объёма документов или сложной log-аналитике.

## Принципы продукта

- факты и улучшение процессов важнее поиска виноватых;
- автор сообщения, владелец причины и исполнитель исправления — разные роли;
- персональная аналитика требует контекста, права доступа и права на комментарий;
- каждое объединение, назначение и изменение статуса сохраняется в аудите;
- метрики не должны стимулировать сокрытие проблем или массовое дробление/объединение записей;
- персональные данные, токены Bitrix24 и вложения защищаются серверной авторизацией.
