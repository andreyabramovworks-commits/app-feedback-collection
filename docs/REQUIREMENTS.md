# Требования к MVP «Пульс проектов»

## Роли

В приложении только четыре роли: **сотрудник**, **руководитель**, **ОКК**, **администратор**. Роль «руководитель проекта» не используется. Исполнитель не является ролью приложения: задача исполняется в Bitrix24.

## Обязательные сценарии

1. Сотрудник видит CRM‑проекты Bitrix24, по которым обязан сдать форму, и отправляет отдельную карточку для каждой проблемы/идеи либо отмечает «проблем не заметил». Обязательную форму запускает и перевод CRM‑проекта в согласованный статус, и отдельная кнопка руководителя.
2. Любой сотрудник может добровольно написать по видимому проекту.
3. Анонимность включена по умолчанию; настоящий автор доступен только администратору.
4. ОКК фиксирует контрольные точки, сортирует входящие, вручную объединяет дубли и проводит разбор по завершении проекта.
5. ОКК создаёт из разбора настоящую задачу Bitrix24, предварительно проверив текст, срок, ответственного и наблюдателей.
6. Сотрудники и руководство видят дашборды и могут открыть первичную карточку из графика.

## Карточка

- CRM‑проект;
- тип: ошибка / нарушение процесса / идея / инцидент;
- отдельный заголовок и описание;
- проблемы были / проблем не заметил;
- анонимно / публично;
- предполагаемая ответственность: человек, несколько людей, роль, отдел или процесс; её видят только ОКК и администратор, а сотрудник до разбора видит пояснение, что это внутреннее поле и оно не будет показано указанному человеку;
- назначенный ОКК или администратором ответственный: это единственное назначение, которое видит сотрудник;
- предложение решения;
- фото/файлы с проверкой формата и размера;
- статус разбора, комментарии, история;
- связанная задача Bitrix24.

Не нужны отдельные поля «насколько серьёзно» и «как быстро решить» для проблем. Срок обязателен только у итоговой задачи Bitrix24.

## Статусы проблем

`Новая`, `Ждёт разбора`, `На разборе`, `Задачи поставлены`, `Закрыта`. Дубликат — связь карточек, а не самостоятельный статус.

Новые записи сразу видны всем по правам; ОКК разбирает их по окончании проекта совместно с руководством.

## Дашборды

- Компания: сдача форм, количество проблем/идей, задачи после разборов, динамика.
- Проект: кто сдал форму, контрольные точки, карточки и связанные задачи.
- Сотрудник: количество зафиксированных им публичных проблем, проблемы с окончательно назначенной ОКК/администратором ответственностью, календарные дни без ошибок, предложенные и реализованные инициативы, обязательные формы и задачи.

Начинаем с первого проекта и первой записи. Публичный рейтинг «лучший/худший» не вводим; показатели показываются с контекстом.

## Внешний вид и вкладки

- mobile-first для сотрудников, ПК‑админка для ОКК;
- русский, светлая/тёмная тема, доступные крупные элементы;
- в MVP интерфейс содержит полный каркас вкладок;
- неготовые вкладки явно помечены «Будет в следующем релизе», показывают назначение и примерный визуальный сценарий, но не притворяются рабочими.

## Инфраструктура

- облачный Bitrix24, локальное приложение;
- отдельный Docker Compose‑набор приложения на сервере, не смешанный с другими сервисами;
- PostgreSQL и вложения на сервере; фото автоматически сжимаются;
- stage и production;
- до 60 пользователей, до 15 одновременных;
- технические отчёты/уведомления приходят администратору по email;
- доступность интерфейса обязательна: крупные кнопки, контраст, не только цветовые статусы.

## Не входит в MVP — будущие релизы

- автоматическое закрытие задачи Bitrix24 после сдачи формы;
- автоматические предложения/слияние дублей по ключевым словам;
- импорт старых Excel/Bitrix‑данных; сначала чистый тестовый лист, затем обнуление;
- Excel/CSV/API‑выгрузки; в MVP — только PDF‑выгрузка для администратора;
- расширенные сравнения сотрудников и новые показатели сверх первого набора;
- автоматические правила сроков для проблем;
- полноценные функции вкладок‑анонсов, включая конструктор отчётов, расширенные уведомления, автоматические напоминания и дополнительные интеграции;
- Elasticsearch, Kibana, Logstash, микросервисы и ML‑классификация.
