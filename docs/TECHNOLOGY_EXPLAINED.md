# Технологии простыми словами

## Что увидят сотрудники

Сотрудники увидят формы, проекты, админку и понятные интерактивные графики. **ECharts** — библиотека внутри приложения, которая рисует диаграммы: можно нажать на столбец и открыть конкретные карточки. Это не отдельная программа.

## Где хранятся данные — PostgreSQL

**PostgreSQL** — надёжная «умная таблица» на сервере. В ней будут проекты, сообщения, задачи и точные цифры для графиков. Она отвечает на вопрос: «Сколько проблем закрыли по этому проекту за месяц?» Для MVP с 60 пользователями этого более чем достаточно.

## Как следить за техническим здоровьем

| Инструмент | Простое объяснение | MVP |
| --- | --- | --- |
| OpenTelemetry | Единый след запроса: что приложение сделало и где ошиблось. | Да, настраивает разработчик. |
| Prometheus | Счётчики: сервер жив, сколько ошибок, как быстро отвечает. | Да. |
| Grafana | Экран технических графиков и предупреждений для владельца/разработчика. | Да. |
| Loki | Аккуратный журнал ошибок и событий. | Да, если хватает ресурсов сервера. |
| Sentry/GlitchTip | Сообщает разработчику о сбоях у пользователя. | Рекомендуется. |
| Elasticsearch + Kibana | Тяжёлый поиск по огромным журналам. | Нет в MVP. |
| Logstash | Сложный переводчик логов из множества систем. | Нет в MVP. |

## Почему не всё сразу

PostgreSQL, ECharts и базовое наблюдение — это кухня, касса и пожарная сигнализация небольшого кафе. ELK — отдельный склад и служба логистики: полезны при больших объёмах, но на старте потребуют больше настройки, чем дадут пользы.

### Решение MVP

1. Продуктовые данные и графики: PostgreSQL + API приложения + ECharts.
2. Техническое здоровье: OpenTelemetry + Prometheus + Grafana; Loki/GlitchTip при наличии ресурсов.
3. Elasticsearch/OpenSearch — только если обычного поиска по карточкам станет недостаточно или логов будет действительно много.

## Что понадобится позже

- Docker и контейнеры приложения, базы и мониторинга;
- ежедневная резервная копия базы и регулярная проверка восстановления;
- место для фото и копий;
- HTTPS‑домен;
- stage‑окружение, где обновление проверяют до сотрудников.
